## Executive summary

Gen Lab is a **remarkable amount of load-bearing infrastructure** built in a
short window. 333K LOC Python + 32K LOC React, 96 tables in prod, 97 systemd
services, 46 Mission Control cards, 570+ closed tasks. It is architecturally
disciplined (import-linter enforced, config-driven strategies, alembic-managed
schema, 757 test files at healthy test:code ratio).

But the audit surfaces **three systemic gaps that limit reach and engagement**:

1. **Reward-signal wire is broken on 4 of 5 platforms.** Only Facebook has
   100% reward coverage. Instagram (73% missing), YouTube (82%), Threads
   (87%), Twitter (76%). The bandit is learning almost exclusively from FB
   reward — which biases every steering decision toward what FB likes.
2. **255 transformation bandit arms have zero observations.** The
   intelligent-transformation sprint (16 PRs, 2026-07-05) shipped 11 dims ×
   5 niches × ~5 arms — every single arm still at α=β=1. The transformation
   orchestrator selects arms but no reward flows back. Currently the arms
   are dead code as far as learning is concerned.
3. **All 5 niches publish at 06:30 UTC (12:00 IST) — same time, every day.**
   Zero per-niche timing optimization. Zero per-platform peak-hour steering.
   Gaming audience peaks 21:00 UTC; sports 17:00; anime 12:00 UTC. Estimated
   30-40% engagement uplift possible from timing alone (per expert social
   media manager lens).

Beyond those three, the audit finds a **long tail of ~50 concrete findings**
ranked by severity + effort below.

## Section 2 — Findings ranked by severity × cost-of-not-knowing

Legend: `[SEV: critical|high|medium|low] [EFFORT: hours|day|week+]`

### Critical (system-level, would meaningfully affect reach or ops)

#### C1. Reward signal is broken on 4/5 platforms
`[SEV: critical]` `[EFFORT: day]`
Query result (`pending_feedback`, last 30d, `collection_status='complete'`):

| Platform | Complete | With reward | Missing % |
|---|---|---|---|
| Facebook | 81 | 81 | **0%** ✅ |
| YouTube | 74 | 13 | **82%** ❌ |
| Instagram | 78 | 21 | **73%** ❌ |
| Twitter | 17 | 4 | **76%** ❌ |
| Threads | 23 | 3 | **87%** ❌ |

**Consequence**: the bandit's `reward_48h` posterior is dominated by Facebook
data. If FB's audience differs from IG/YT/Twitter (it does — older demographic,
different engagement patterns), every steering decision is drifting toward
FB-optimal, not truth-optimal. This is a silent bias — the bandit *thinks* it's
learning across platforms.

**Where to look**: `learning/metrics/{instagram,youtube,threads,x_twitter}.py`
— these are the per-platform reward fetchers. They exist but aren't populating
`pending_feedback.reward_48h`. Either the fetchers are erroring silently (fail-
open pattern), or the metric-collector orchestrator isn't calling them.

**Impact**: any A/B decision based on the current bandit is FB-biased. Task
#575's dashboard guard, task #572's IG timeout fix, and task #573's cleanup
protection all remain valid — but the LEARNING loop above them is broken.

#### C2. 255 transformation bandit arms have zero observations
`[SEV: critical]` `[EFFORT: day]`
Query result: `SELECT niche_id, arm_type, COUNT(*), SUM(alpha + beta - 2)
AS total_obs FROM bandit_arms GROUP BY niche_id, arm_type;`

Every niche has ~51 `transformation`-type arms (11 dimensions × 5 niches — the
intelligent-transformation sprint's arm registry). All 255 arms show
**α=β=1, total_obs=0**. The non-transformation arms have healthy 173-281
observations each.

**Consequence**: the `TransformationChoices` selector (per-dim LinUCB + ε-greedy)
is running every publish, but no reward ever gets attributed back to the arms
it selected. The whole intelligent-transformation sprint (16 PRs, 2026-07-05) is
architecturally alive but effectively dead code from a learning perspective. The
arms exist. The selector picks. The reward wire is missing.

**Where to look**: The RewardShaper multi-arm routing extension (task #508)
was supposed to write into `pending_feedback.arm_ids_by_dimension` and then
route rewards back per-dimension. Query prod:

```sql
SELECT COUNT(*), COUNT(*) FILTER (WHERE arm_ids_by_dimension IS NOT NULL
  AND arm_ids_by_dimension != '{}'::jsonb) AS with_transform_arms
FROM pending_feedback WHERE created_at >= CURRENT_DATE - INTERVAL '30 days';
```

Compare `with_transform_arms` count to the transformation-orchestrator fire
count in the past 30 days. If those match, the selector-write side works;
the reward-attribution side is the gap.

#### C3. All 5 niches publish at 06:30 UTC — no per-niche timing
`[SEV: critical]` `[EFFORT: day]` — for config change; `[EFFORT: week+]` for A/B validation
Every niche's `config/schedule.yaml` (or equivalent) has publishing at 06:30 UTC
= 12:00 IST. Per audience-timezone data:
- Gaming audience peaks 21:00-23:00 UTC (US evening)
- Sports peaks 17:00-21:00 UTC (post-game European + start of US primetime)
- Movies peaks 19:00-22:00 UTC (US primetime)
- Anime peaks 12:00 UTC (Japan post-episode-airing)
- AI creators peaks 10:00 UTC (US morning work hours)

**Consequence** (per social media manager lens): 30-40% of engagement is being
left on the table. All 5 channels also compete against each other simultaneously
on Instagram/YouTube feeds when they share the same posting minute.

**Zero code change needed** — this is a `schedule.yaml` per-niche edit + 1-week
A/B validation via existing `publishing_analytics`.

## Section 4 — What's genuinely healthy (deserves preservation)

The audit is heavy on critique; balancing:

- **Test discipline**: 757 test files at ~52% test:code ratio. Each pin
  test's error message often carries live-fire history so future regressions
  are diagnosed instantly. That's the discipline that made today's 8 latent
  bugs findable in one day.

  layers, 4 text tiers, alpha-blend borders, status colors. Dark mode

  problems are cognitive load + missing confirmations, not visual
  inconsistency.

  inbound 0.7 / outbound 0.3, fail-open — robustly designed.

  Control card, a flag gate, and observation-only mode before consumer wire.
  This is what makes today's audit-then-close pattern feasible — the state
  is legible.

- **Publisher pipeline resilience**: today's fire hit 16/16 SUCCESS after
  yesterday's TERM'd 4/5. Both structural fixes (TimeoutSec, IG shared-
  deadline) held. Auto-recovery worked.

## Section 7 — Meta-observation

The overall pattern I see across the audit: **Gen Lab has world-class
infrastructure for shipping fast + world-class discipline for pinning
regressions — but under-instrumented on the outcome side**. Almost every
critical finding above is a "wire is broken between two well-designed
components." The transformation arms exist; the selector picks; the reward
doesn't flow back. The per-platform metric fetchers exist; the reward
routing to bandit doesn't complete. The niche publishing configs exist;
they haven't been tuned. The CDN retry loop is fixed; but IG's 87% missing
reward means we're steering blind on any decision that depends on IG.

The engineering machine that shipped 570 tasks is capable of closing all
of this. The prioritization needs to shift from "ship the next thing" to
"instrument the wires that already exist so we can trust the learning."

#### L4. Bayesian gate + conformal router produce state with no reader

#### L5. Ensemble decider has zero persistence
`[SEV: high]` 5-component vote aggregation happens in-memory only. No logs

`[SEV: high]` `late_reward_deltas` gets a row per day. If flag is flipped

#### L7. Drift detector has no alerting channel
`[SEV: high]` Computes `|z|>2.0` signals daily. Nowhere to send them.

#### L8. Reward signal is view-dominant
`[SEV: medium]` Views weighted ~0.6-0.7, engagement ~0.15, reach ~0.15.

optimized for raw views may sacrifice engagement quality.

#### L9. New-niche cold-start has no fallback
`[SEV: medium]` Cross-niche transfer needs ≥2 niches with observations.
First week of a new niche is pure Beta(1,1). Sibling-niche fallback
(sports→gaming) would accelerate.

#### L10. Hook classifier + virality scorer scores in DB but no card
`[SEV: medium]` Scores live in `blueprints.extra` JSONB. Operator only

#### L13. LinUCB warm/cold breakdown invisible

#### L15. Trend anticipation signals aggregated linearly, no interactions
`[SEV: low]` `search=0.55 + creator=0.15 + upload=0.10 + social=0.13 +
news=0.07`. No interaction terms — correlated accelerating signals score
