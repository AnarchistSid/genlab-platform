MAPPING ISSUES (Frontend -> Backend mismatches)
=============================================

  1. /api/video/<candidate_id> BROKEN
     Frontend generates URLs like /api/video/cce9db6f1776211f... (candidate_id, hex hash)
     Backend route validates with RECORD_RE = r'^\d+$' (digits only)
     Result: ALL /api/video/ URLs with candidate_id return HTTP 400 "Invalid blueprint ID"
     Affected: Published blueprints whose all_media_urls use /api/video/ pattern
     Workaround: Some blueprints use /api/media/ pattern which works correctly

  2. /legal/status NOT A REAL ROUTE
     Frontend may route to /legal/status but no backend handler exists.
     Flask legal_bp only registers /legal/privacy and /legal/deletion.
     The SPA catch-all returns index.html which is wrong for a legal status check.

  3. /api/v1/config/schedule-slots returns empty for most niches
     Backend expects publishing.yaml to have: instagram.schedule_slots
     Gaming's publishing.yaml has no schedule_slots key under instagram.
     Anime's publishing.yaml either doesn't exist or has different structure (404).
     Only works if BB (Content Scraper) publishing.yaml has the key.

  4. /api/v1/config/platforms returns empty for all niches
     Backend reads: publishing.yaml -> platforms -> enabled_platforms
     Gaming's publishing.yaml has: platforms -> enabled (list), not enabled_platforms
     Key name mismatch causes empty results.

  5. /api/v1/config/source-filters returns empty
     Backend reads: sources.yaml -> sources (list of objects with platform key)
     Gaming's sources.yaml uses a different structure (not a flat sources[] array).
     Result: Filter dropdown in Stories Explorer is always empty.

  FrameDrift    #7B3FE4         #EC4899 (WRONG)         #7B3FE4 (correct)

  niches_registry.yaml is the source of truth for the backend /api/v1/niches
  and /api/v1/cross-niche/overview endpoints. This means:
    - Mission Control niche tiles use WRONG colors (from API, via niches_registry.yaml)
    - Pipeline status card also uses wrong accent_hex from API
    - Frontend registry.ts has CORRECT colors but is only used by getActiveNiches()
      in Analytics niche selector and NicheTilesCard local overlay

  Impact: BB shows indigo (#6366f1) instead of cyan (#00D4FF),
          SpliceReel shows yellow (#EAB308) instead of gold (#C9A84C),
          FrameDrift shows pink (#EC4899) instead of purple (#7B3FE4).
